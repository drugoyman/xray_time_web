## 13–14 октября 2026

Проверены SSH, системный WireGuard, 3x-ui и Xray. У импортированного клиента
Hiddify отсутствовал TLS server_name: адресом был IP, сертификат выдан домену.
Проверка сертификата по IP воспроизводимо завершилась hostname mismatch.

В inbound 43 установлен `tlsSettings.serverName = yugoo.su`. Сделана резервная
копия базы с суффиксом `.bak-sni-20261013-051405` (метка имени — UTC), контейнер
перезапущен, TLS и передача через VLESS проверены с HTTP 200. Идентификаторы
доступа не менялись. Старые клиенты без SNI сами от изменения сервера не обновляются.

Существующие аккаунты проверялись по их UUID без публикации. QR с прозрачностью
удалось прочитать после композиции на белом фоне; публичных QR здесь нет.

### Разница базы относительно 26.10, 18:27 МСК

Сравнение сделано 27.10 в памяти с `snapshot/x-ui.db` из архива
`vpn-20261026T152721246038Z.tar.gz`. Это разница двух снимков, а не точный журнал
времени каждого редактирования.

| Объект | Разница |
|---|---|
| Все inbounds | Количество сохранено: 29 → 29 |
| Trojan 26897 (ID 10) | Клиентов 10 → 11; у сопоставленных существующих клиентов поля не изменились |
| Trojan 26637 (ID 29) | Клиентов 13 → 14; у сопоставленных существующих клиентов поля не изменились |

| Настройки панели settings | Значения ключей в двух снимках совпадают |
| Схема inbounds | Появились all_time, last_traffic_reset_time, traffic_reset; совместимо с миграцией новой версии |

Deploy-скрипт явно исправляет keyFile Trojan на `/root/cert/yugoo.su.privkey.pem`.
Ранее в логах встречалось `invalid X509 key pair`: вместо приватного ключа
парсер видел блоки сертификатов. Не следует переносить эту ошибку на VLESS 443:
он отдельно проходил проверку TLS.

Сетевой тайм-аут прямого доступа наблюдался **до вечернего обновления**.
Обновление не является установленной причиной исходной недоступности.

всё ещё недоступны напрямую. DNS, клиенты, база, VPN-сервисы и Drive не менялись.
