# Эксплуатация

Команды ниже выполняются на Linux-сервере с уже предоставленным доступом.
Исходники в репозитории — копии, автоматического deploy нет.

## Проверка без изменения сервисов

```sh
uptime
docker ps --filter name=3x-ui
systemctl is-active docker wg-quick@wg0 fail2ban
ss -lnt '( sport = :22 or sport = :443 or sport = :4200 )'
systemctl status vpn-safe-health.timer vpn-safe-backup.timer --no-pager
cat /var/lib/vpn-safe/health.json
```

Health-скрипт пишет новый локальный health.json; он не перезапускает сервисы.
Он проверяет локальные TCP/TLS, HTTP панели, ресурсы, свежесть бэкапа и процессы.
Он **не** выполняет внешнюю VLESS-авторизацию и не доказывает доступность из офиса.
Для TLS панели локальная HTTP-проба отключает проверку сертификата; эта проба
проверяет ответ панели, а не доверие к её сертификату.

## Локальные резервные копии

Скрипт `ops/scripts/vpn-safe-backup.py` использует SQLite online backup,
проверяет `PRAGMA integrity_check`, собирает настройки и архив, записывает SHA-256.
Таймер: 03:30 UTC + случайная задержка до 15 минут (06:30–06:45 МСК).
Проверенная копия 27.10, 06:37 МСК создана успешно.

Архив содержит секреты, включая закрытые ключи и runtime-конфиги. Он должен
оставаться в закрытом серверном каталоге; публикация архива запрещена.
Сам скрипт не реализует ротацию старых копий и проверку полноценного восстановления.

## Google Drive

`vpn-safe-offsite.py` шифрует архив age, отправляет через rclone и сверяет MD5
удалённого файла. Требует отдельно предоставленных конфигурации OAuth и age recipient.
Приватный ключ расшифровки должен храниться отдельно от сервера и репозитория.

Текущее состояние: последняя попытка 26.10 неуспешна с 403 RATE_LIMIT_EXCEEDED
общего Google API проекта rclone; offsite.timer отключён. Успешная доставка
резервной копии не подтверждена. Таймер в Git — сохранённая настройка, а не
утверждение, что он включён. Перед включением нужен собственный OAuth client
или другое проверенное хранилище и тест скачивания/расшифровки.

## Обновление и откат

В `ops/historical/2026-10-26` сохранены исходники одноразового обновления
и отката. Они привязаны к конкретному образу, путям и снимку БД.
Проверка синтаксиса этих файлов не означает, что их можно безопасно повторно запускать.

`rollback-288.py --check` по исходному коду только проверяет предпосылки.
`--apply` останавливает Xray, восстанавливает прежнюю БД и образ, теряет более
новые изменения активной базы, сохраняя отдельную копию перед откатом.
Не запускать откат в качестве способа устранения неподтверждённой сетевой проблемы.

Нужны свежий бэкап, проверенные права доступа, комментарий в чат, запись в журнал,
контроль активных клиентов и последующая проверка реального трафика.
Системный wg0 отделён от контейнера; WireGuard внутри Xray при перезапуске прервётся.

## Второй IP

Timeweb Cloud допускает дополнительные платные IPv4 с ограничениями по типу сети.
Агент не заказывал IP. По скриншоту владельца 27.10 адрес 89.19.209.17 уже указан
у нужного сервера, но проверка 10:04 МСК показала его отсутствие в Linux/netplan.
После назначения адреса в ОС проверить маршруты, listener и
доступ с проблемной сети. Только затем обновлять DNS/экспорт, сохраняя корректный SNI.

Источник: [сетевые настройки Timeweb Cloud](https://timeweb.cloud/docs/cloud-servers/manage-servers/network).

Также: [добавление дополнительного IP в Linux](https://timeweb.cloud/docs/unix-guides/adding-ip-addresses).

### Выполнено 27.10, 10:06–10:08 МСК

Адрес 89.19.209.17/24 назначен на eth0 командой `ip address add`.
Для сохранения добавлен [отдельный overlay](../ops/network/99-vpn-secondary-ip.yaml)
в `/etc/netplan/99-vpn-secondary-ip.yaml` (0600). Существующие DHCP-конфиги,
основной IP, DNS и default route не менялись. `netplan generate` прошёл,
полный `netplan apply`, перезапуск сети и reboot не выполнялись.

Перед изменением сохранены netplan, адреса и маршруты в
`/var/backups/vpn-safe/network-secondary-20261027T070649Z`.
На время внешней проверки установлен автоматический rollback только вторичного
runtime-адреса через systemd timer; после успешных проверок и записи конфигурации
timer остановлен. Существующие VPN-процессы не перезапускались.

Проверено с CRM: оба IP отвечают на ping, доступны 22/443, реальный VLESS-запрос
через каждый IP получает HTTP 200 с SNI yugoo.su. Прямое подключение из проблемной
сети по-прежнему с тайм-аутом. DNS и экспорт профилей не переключались.

Netplan сообщил предупреждения о широких правах двух ранее существовавших YAML.
Новый файл имеет 0600; права старых файлов в этой задаче не изменялись.
