# Клиентские профили

Основное подключение: VLESS, TCP, TLS, сервер `89.19.210.13:443`, SNI `yugoo.su`.
Flow пустой. В проверенных экспортированных профилях fingerprint chrome,
ALPN h3,h2,http/1.1. Эта комбинация отражает текущий экспорт, а не утверждение
об универсальной совместимости всех клиентских приложений.

## Hiddify

Если адрес — IP и проверка сертификата включена, в блоке TLS нужен server_name:

```json
{
  "type": "vless",
  "tag": "VPN — пример без доступа",
  "server": "89.19.210.13",
  "server_port": 443,
  "uuid": "<UUID_ИЗ_ЗАКРЫТОЙ_ПАНЕЛИ>",
  "tls": {
    "enabled": true,
    "server_name": "yugoo.su",
    "utls": {"enabled": true, "fingerprint": "chrome"}
  }
}
```

Это шаблон с заглушкой, его нельзя импортировать как готовый доступ.
Сертификат не выдан для IP, dns.google или cloudflare-dns.com. Подмена SNI
этими значениями при проверке сертификата воспроизводимо даёт mismatch.

## Streisand / iPhone

Импортировать свежую ссылку из 3x-ui, выбрать именно новый профиль.
Статус VPN «подключено» означает запуск локального туннеля, но не доказывает
успешную передачу данных через сервер. Если сайты не открываются, нужны журнал
приложения и сравнение Wi-Fi с мобильной сетью.

## Изменения адреса и существующие клиенты

- Изменение serverName в панели не обновляет автоматически локальный импорт.
- Если подписка используется, получить её обновление и проверить результат.
- UUID прежних клиентов при исправлении SNI 13.10 не менялись.
- Клиент с зафиксированным старым IP не переключится при смене A-записи домена.
- `yugo.su` (одна o) — другой домен. Его ping не относится к нашему серверу.

## QR

QR содержит секрет доступа и в публичном репозитории не хранится. Проверенный
присланный PNG использовал чёрные пиксели и прозрачный фон: на чёрном фоне он
выглядел сплошным квадратом, но декодировался при отображении на белом.
