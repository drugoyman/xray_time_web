# Изолированная проверка WireGuard

Утилита проверяет WG handshake, DNS внутри туннеля, TCP и доверенный HTTPS,
не меняя общую сеть компьютера. Используется официальный
`wireguard-go/tun/netstack.CreateNetTUN`: сетевой стек только в памяти процесса.
Системный TUN-адаптер не создаётся. Windows routes, DNS и proxy не записываются.
Обычный UDP-сокет к Endpoint — единственный внешний транспорт процесса.

## Запуск

Нужен Go, соответствующий go.mod. Ключи хранятся только в отдельном локальном
профиле, который не входит в Git.

```sh
go test ./...
go build -trimpath -o ../../.private-import/wg-isolated-check.exe .
../../.private-import/wg-isolated-check.exe -config /private/test-client.conf -url https://example.com/
```

Использовать отдельный временный WG-пир, а не профиль действующего клиента:
одновременное использование одной пары ключей на разных устройствах вызывает
переключение endpoint. После проверки удалить временный peer и секретные файлы.
Программа сама не добавляет/удаляет серверные peers и не устанавливает драйверы.

Поддерживается один Interface и Peer, IPv4-адрес и DNS, IP:port Endpoint.
Маршрут 0.0.0.0/0 существует только во внутреннем стеке. HTTP proxy отключён
внутри собственного транспорта. Ключи преобразуются в UAPI только в памяти.
В stdout выводятся HTTP-статус, размер тела, время, handshake timestamp и
счётчики. Полный UAPI, профиль, ключи и тело ответа не выводятся.
`os_network_modified=false` описывает способ реализации, а не заменяет внешнюю
проверку снимков Windows до и после запуска.

## Проверка 27.10.2026, около 10:44 МСК

- Windows, без системного VPN-туннеля: временный peer 10.70.0.5.
- Endpoint 217.18.60.102:51820 → CRM NAT → VPN 89.19.209.17:51820.
- HTTPS https://example.com/: 200, 577 байт, около 562 мс.
- Клиент: rx 7788 / tx 2932 байт, handshake установлен.
- Сервер: свежий handshake (40 секунд к моменту проверки), endpoint — CRM,
  rx 3140 / tx 7820. Счётчики получены в разные моменты и не обязаны совпадать.
- Снимки IPv4 routes, IPv4 DNS и системного proxy Windows совпали до/после.
- Временный peer удалён, автотаймер удаления остановлен, секретные runtime-файлы
  удалены с сервера и ПК. Пользовательский peer 10.70.0.4 не менялся этим тестом.
- WG на сервере active, CRM healthz 200, relay service active.

Сборка: Go 1.27.3 из официального go.dev, SHA-256 архива проверен.
Зависимость wireguard-go закреплена в go.mod, транзитивные зависимости в go.sum.
Runtime, caches, исполняемый файл, профили и сетевые снимки остаются в
игнорируемой .private-import, не в репозитории.

Источник подхода: [официальный пример WireGuard netstack](https://github.com/WireGuard/wireguard-go/blob/master/tun/netstack/examples/http_client.go).
